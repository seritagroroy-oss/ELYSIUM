Document de Vision : Évolution Architecturale (Phase 2)

Projet : ELYSIUM - Module de Pointage
Sujet : Futures mises à jour de type "Scale-Up" (Hautes Performances)
Statut : En pause (Attente de validation stratégique)

Note de sécurité : Ces implémentations sont jugées comme étant à "Haut Risque" pour la stabilité visuelle et structurelle du système actuel. Elles nécessitent d'être développées et testées sur un serveur miroir (environnement de pré-production) avant toute mise en ligne.

1. Virtualisation du Tableau de Bord (React-Window)

Actuellement, le tableau de pointage dessine l'intégralité des cellules pour tous les agents du mois. Si le nombre d'agents dépasse 1000, le navigateur risque de ralentir considérablement.

Le Plan :

  • Suppression de la structure HTML classique (<table>, <tr>, <td>).
  • Remplacement par une liste "virtuelle" qui calcule mathématiquement la position du défilement (scroll).
  • Comportement : Le navigateur ne dessinera physiquement que les 20 lignes visibles à l'écran. Lors du défilement, ces 20 lignes sont instantanément recyclées avec les nouvelles données.
Avantage final : L'ouverture du tableau de bord prendra exactement le même temps avec 50 agents qu'avec 10 000 agents.

2. Architecture "Offline-First" (Pointage sans Internet)

Afin de pallier les coupures de courant ou de réseau fréquentes, le module de pointage doit pouvoir fonctionner en totale autonomie déconnectée.

Le Plan :

  • Implémentation d'un Service Worker pour intercepter le trafic réseau et mettre en cache l'interface utilisateur.
  • Mise en place d'une base de données locale (IndexedDB) dans le navigateur Google Chrome de l'utilisateur.
  • Création d'un gestionnaire de file d'attente (Sync Manager) qui tente de renvoyer les données à MySQL dès que la connexion internet est détectée à nouveau.
Avantage final : Productivité ininterrompue. Les agents de saisie ne sont jamais bloqués par les aléas du réseau.

3. Temps Réel Multijoueur (WebSockets)

Dans le cas où plusieurs superviseurs ou gestionnaires travaillent sur la même grille de pointage en même temps, il faut éviter les écrasements de données.

Le Plan :

  • Mise en place d'un serveur WebSocket (Daemon) fonctionnant en permanence à côté du serveur web classique.
  • Le module de pointage maintient une connexion ouverte (Socket) avec le serveur.
  • Dès qu'un pointage est fait sur l'ordinateur A, l'ordinateur B reçoit instantanément le signal et modifie la case à l'écran sans rafraîchir la page.
Avantage final : Visibilité en temps réel de l'activité. Collaboration semblable à celle d'un document Google Docs.
